# msd stack 是一个 AI Agent 优先的量化策略框架

> 结论先行：**msd stack 的接口形态是"为机器读者设计"的**——契约内嵌在代码里、策略是单文件纯 Python、危险的基础设施被下沉为框架不变量、输出是结构化的、结果是确定性的。这几条构成"AI Agent 优先"的实质内核。
> 但它的成熟度还差三件套：**报错升级（禁止静默降级）、数据覆盖率前置、文档入口**。缺了这三样，Agent 仍然能写出正确策略，但很难在出错时自救。
>
> 本文的论据全部来自一次真实开发：用 msd stack 从零实现"戴维斯双击"组合策略（`strategy/010/davis_double_play.py`），全市场 5029 只标的、1007 根日线、12 次调仓、65 笔成交。

---

## 1. 先立标尺：什么叫 "Agent 优先"

"人类友好"和"Agent 优先"不是同一件事。人类能靠直觉、常识、经验补齐框架没写的东西；Agent 不能。因此判定一个框架是否 Agent 优先，看六条：

| # | 判据 | 反例（人类可忍、Agent 不可忍） |
|---|---|---|
| ① | **契约同仓可机读**：接口约定在代码里，一条命令可检索 | 契约在 Confluence、录屏、口头传承 |
| ② | **最小迭代闭环**：改一个文件 → 一条命令 → 拿到结果 | 改配置、跑代码生成、编译、重启服务 |
| ③ | **不可验证的正确性下沉**：前视偏差、撮合、复权等"写错也看不出来"的部分由框架保证 | 让使用者自己写对齐逻辑，再用收益曲线"验证" |
| ④ | **数据自描述 + 可抽样验证** | 字段靠猜，口径靠问人 |
| ⑤ | **输出可结构化消费**：指标、诊断能被子程序解析 | 只有一张 PNG 曲线图 |
| ⑥ | **确定性 + 可自我证伪**：同输入同输出；能自主做样本外/多起点检验 | 随机种子藏起来；只有一条回测跑道 |

下面逐条对照。

## 2. 逐条论证

### 2.1 契约内嵌：docstring 就是 API 文档，且能被 `pydoc` 直接取出

`mbt` 把关键契约写在类的 docstring 里，位置正好是"实现旁边"，因此永远不会过期到离谱，也能被 `grep` / `pydoc` 直接读到：

```bash
uv run python -m pydoc mbt.select.panel.Panel
```

真实输出（节选）：

- `Panel.column()` 返回 `(n_objs, bars)` 二维视图，`buffer()` 返回块布局一维缓冲；
- `load_kline` 的 **Layout contract**：`block i = data[i*bars:(i+1)*bars]`，缺失 bar 用 NaN 填充（"全 NaN 行"意味着停牌/未上市，不是无数据）；
- **baseline 陷阱**被显式写明："若 baseline 停牌/退市/次新，其他标的会被静默截断或移位，不报错；推荐 `baseline="SH000001"`"；
- `objs` **可能被重排**："Never map results to your input list positionally"；
- `load_financial` 的单位约定："Values are in CNY unless the field is a ratio, which is in percent"；
- `Selector` 的生命周期契约："子类按 step00, step01, ... 顺序实现，每步接收上一步结果；**每个 stepXX 必须有 docstring**（会被写入日志）；中间因子累积到 `self.factors`（列名 `obj`）"。

**为什么这对 Agent 关键**：Agent 无法"问同事"，只能读。契约在代码里，意味着"读源码"和"读文档"是同一次操作，不需要跨系统拼信息。

> 诚实标注：本次开发我**是先把策略写完、才想起来跑 `pydoc` 的**。补做后确认，上面这些契约早就写在 docstring 里——包括我自己踩到并归因为"没有文档"的 baseline 陷阱、块布局、单位约定。也就是说信息一直都在，只是没有入口。**文档存在 ≠ 文档可达**，这是当前成本最低、最该先修的一条（`README.md` 目前是 0 字节）。

### 2.2 最小闭环：单文件 → 一条命令，且自动装配

一个策略就是**一个 `.py` 文件**，里面同时定义 `Selector` 与 `Strategy`：

```python
class Selector(mbt.Selector):   # 选股
class Strategy(mbt.PortfolioStrategy):  # 调仓
```

CLI 通过扫描模块变量自动识别要实例化谁（`RunRequest.load_strategy` 找 `Strategy` 子类，`try_load_selector` 找 `Selector` 子类），并从 `inspect.signature` 过滤 `-a k=v` 参数。没有注册表、没有装饰器、没有 proto 生成、没有编译。

实际闭环只有三步：

```bash
# 1. 写/改文件
# 2. 试跑选股（只看选股逻辑，秒级）
python -m mbt.select.cli strategy/010/davis_double_play.py -s A_STOCKS_EXCLUDE_ST -f
# 3. 跑回测（看组合行为）
python -m mbt.run.cli strategy/010/davis_double_play.py -s A_STOCKS_EXCLUDE_ST \
    -b 2022-09-08 -e 2026-11-11 -S
```

**实测成本**：全市场选股一次 **0.258 秒**，漏斗为 5029 → 3737（快照排雷）→ 3417（TTM 亏损剔除）→ 3389（流动性/上市时长）→ 3351（有效 PE 截面）→ 1676（质量合格）→ 499（可买：低 PE + 增速带）→ 20 只。全市场组合回测（5030 objects × 1007 bars = 507 万行）数分钟内完成，"数据构建"一步 0.53 秒。

**为什么这对 Agent 关键**：Agent 的能力上限约等于"单位时间内能完成的 edit-run-observe 循环次数"。闭环越短，可尝试的假设越多、越敢重构。若每次都要生成代码、改配置、重启，Agent 会倾向"一次写对"，而这是最不可靠的策略。

### 2.3 把"写错也看不出来"的正确性，下沉成框架不变量

这是整套框架**最像 agent-first 设计**的地方。量化里最危险的不是算错指标，而是**前视偏差**——它不会报错，只会让你以为策略很好。

msd stack 把以下事情全部做在框架侧，使用者零代码：

| 下沉项 | 框架机制 | 使用者负担 |
|---|---|---|
| 财报前视偏差 | `mbt.run.msd.load_data` 把报告期（12-31 等）映射为**法定披露截止日**（04-30 / 08-31 / 10-31）再 asof backward 对齐，报告期重命名为 `report_ts` | 0 行 |
| 回测内选股前视 | `ctx.run_selector(selector, lastN=260)` 先 `slice_panel` 到当前 bar，再构造 `_HistoricalPanelSelectorDataProvider`，其 `load_financial` 按 `ts <= current_bar_date` 截断 | 1 行调用 |
| 复权 | `close/raw_close`（复权/未复权）双列并存，PE 用 `raw_close`、走势用 `close` | 0 行 |
| 撮合 | `rebalance_step`：先卖后买、现金不足按比例缩放、手数取整、`tolerance` 容差、涨跌停/停牌跳过 | 1 行 `ctx.rebalance()` |

本次我写了一个 TTM 净利润还原 + 全市场截面 PE 的策略，**没有写过一行对齐代码、一行撮合代码**。`f097`（年内累计净利润）的 TTM 公式是我按会计口径自己推的，但"哪一期的数据在什么时候可见"这个最容易出错的问题，框架已经保证。

**为什么这对 Agent 关键**：Agent 的强项是"生成候选实现"，弱项是"自审不可见错误"。凡是需要人工经验才能发现的正确性问题，都必须由框架兜住，否则 Agent 产出的结果不可信——而 Agent 又恰恰不会怀疑自己。

### 2.4 数据自描述：一条命令拿到 schema，并且可以立刻抽样验证

```bash
./msd shell -s http://127.0.0.1:50510 ".schema stock_financial"
```

输出是结构化的三列表格（`column | type | desc`），180+ 字段带中文语义：

```
| 17|  f097|     f64|   |   利润表 >> 净利润(不含少数股东损益)|
| 27|  f197|     f64|   |     发展能力分析 >> 净利润增长率|
| 8 |  f205|     f64|   |     盈利能力分析 >> 年化净资产收益率|
| 31|  f223|     f64|   |       股本结构分析 >> 资产负债率|
```

拿到 schema 后可以**立即抽样验证假设**，而不是写完整个策略再祈祷：

```bash
./msd shell -s http://127.0.0.1:50510 "select ts from stock_kline_1d where obj='SH600000' limit 1"
# → 2022-09-08，才发现样本只有 4.2 年
./msd shell -s http://127.0.0.1:50510 "select * from stock_financial where obj='SH600000' limit 1"
# → 确认 f097 是年内累计口径
```

本次正是靠抽样发现了两件事：① 日线最早只有 2022-09-08（策略实际的样本上限，而不是我以为的 2016 年）；② `f223` 资产负债率在 Q1/Q2/Q3 常返回 `0.0`，不能直接当有效值用。

**为什么这对 Agent 关键**：Agent 的最高效工作模式是"提出假设 → 最小验证 → 再扩展"。数据自描述 + 可即时查询，把"字段理解"从"人类口述知识"变成了"可执行探测"。

### 2.5 输出可结构化消费：Agent 的自我纠错回路

回测输出的是 markdown 表格，不是只给人看的图：

```
| profit | +21.76% |  | beta | 0.6099 |  | max_drawdown | -23.86% |
| sharpe | 0.3690 |  | trade_count | 65 |  | rebalance_count | 9 |
```

更重要的是 `Strategy.finalize(ctx) -> dict` 这个**自定义诊断通道**，返回的 dict 会进 `Report.diagnostics` 并渲染进摘要。我利用它在策略里埋了退出原因计数器：

```python
def finalize(self, ctx):
    return {"rebalances": ..., "exit_reasons": dict(self.exit_reasons), ...}
```

输出：

```
| quality_drop | 13 |  | valuation_rerated | 2 |  | data_or_liquidity | 4 |
```

**这是全篇最有力的证据**：`valuation_rerated` 在这段代码的第一版里恒为 **0**。策略收益看着还行（+15.55%），任何"看曲线"的检查都不会发现异常；但这个计数器为 0 说明"双击兑现"的卖出通道从未生效——顺着它才定位到真正的 bug：持有判定用了一个**已经被 PE 排名截断过的集合**，导致缓冲带永远是空集。修复后换手从 176 笔降到 65 笔，收益 15.55% → 21.76%。

**为什么这对 Agent 关键**：Agent 需要一个"比收益曲线更细的语义级信号"来判断"逻辑是否按设计运行"。`diagnostics` 就是这样一个可编程的观测点——它把"策略行为"变成了可断言的数值，而不是需要人眼审美的曲线。

### 2.6 确定性与可自我证伪

- **确定性**：同一份代码、同一区间重复运行，指标逐位一致（我实测多次均为 `+21.76% / sharpe 0.3690 / 65 笔`）。策略里没有隐藏随机源、没有时间依赖。
- **可证伪的开关是内建的**：`-b` 支持多起点，`--holdout` 支持样本内外切分，`--warmup-bars` 支持指标预热，`-a k=v` 支持不改代码调参。所以我可以在同一份代码上自主完成"全区间 vs 子区间"的对照：

| 区间 | 策略 | 基准(SH000300) | 结论 |
|---|---|---|---|
| 2022-09 → 2026-11 | +21.76% | +0.53% | 全区间显著跑赢 |
| 2024-01 → 2026-11（反弹段） | +10.36% | +19.87% | 反弹段跑输 |

两条合起来才得出可信结论：这是一个 **beta≈0.61 的防御型价值组合**，弱市有效、反弹段落后——而不是"策略有效"或"策略无效"这种二元判断。

**为什么这对 Agent 关键**：Agent 最容易犯的错不是算错，而是**自我欺骗**（拿着一个区间的漂亮数字当结论）。框架若内建样本外/多起点开关，Agent 的结论质量会被结构性抬高。

## 3. 反证：目前还不够 Agent-first 的地方

要论证得站得住，必须列出反面。以下 8 条**专门伤害 Agent**（而非人类）的缺口，其中标注「实测」的是本次真实触发过的，「代码路径」的是读源码确认存在、本次未触发的分支——后者恰恰更危险，因为 Agent 永远不会知道自己踩上了。

| # | 问题 | 证据 | 为什么专坑 Agent |
|---|---|---|---|
| 1 | **静默降级**：选股池外的标的被丢弃只 warning（代码路径） | `run_selector: {n} selected obj(s) not in pre-loaded pool ... ignored` | Agent 不会"觉得哪里不对"，会继续跑并相信结果 |
| 2 | **`-s` 不传时回测池退化为首日选出的 20 只**（代码路径） | CLI 的 "组合策略未通过 -s/--objs 指定候选池..." warning | 结果从"全市场轮动"变成"20 只固定池"，指标照常输出 |
| 3 | **`fin_fields` 未声明 → 财务数据全空**（代码路径） | `load_financial` 返回空 DataFrame，仅 warning | 选股静默退化为"选不出任何票"或空仓 |
| 4 | **参数被 `inspect.signature` 静默吞掉**（实测规避） | `Strategy` 与 `Selector` 各自持有参数，`-a pe_pct=0.3` 若不在 `Strategy.__init__` 里手工透传则完全无效 | Agent 以为在做参数敏感性实验，实际改的是死参数 |
| 5 | **数据覆盖率无前置校验**（实测） | 只能从 "请求起始日 2023-01-01 早于数据源最早日期 2023-01-03" 的 warning 得知真实起点 | Agent 会基于"以为有 10 年数据"的假设做设计 |
| 6 | **子类 docstring 与基类漂移**（实测） | 基类 `load_financial` 说返回 `['obj','ts',*fields]`，回测 provider 实际多一列 `report_ts` 且过滤语义不同 | 按"文档"写代码的 Agent 会直接 `KeyError` |
| 7 | **报告口径小不自洽**（实测） | `rebalance_count=9` vs `finalize` 的 `rebalances=12`；`profit_factor=0.82` 与总收益 +22% 直觉冲突 | 解析报告做决策的 Agent 会被误导 |
| 8 | **字段级口径缺失**（实测） | `f097` 是"年内累计"而非单季、`f205` 是"年化"、`f223` 季报常为 0 | 只能靠抽样反推，写错不报错 |

这 8 条的共同特征：**它们都是"人类能靠经验补、Agent 只能靠运气补"的缺口**。这也是我把评级定为"接口已成型、成熟度未到位"的原因。

## 5. 要真正坐实 "Agent 优先"，按 ROI 排序补六件事

1. **禁止静默降级（最高 ROI，改动最小）**：增加 `strict=True`，把"池外标的丢弃 / `financial_frame` 为空 / `fin_fields` 未声明 / 基准缺失"从 warning 升级为异常。Agent 最怕的不是报错，是**不报错**。
2. **统一参数契约**：让 `Strategy` 构造 `Selector` 时自动透传全部 `-a` 参数（或 `instantiate_class` 对未识别参数直接抛错），消灭"改了但没生效"。
3. **数据覆盖度前置检查**：`msd-bt info --coverage` 输出标的池的日线/财务可用区间与字段非空率，并在回测启动时打印"样本长度 4.2 年"这种断言级信息。
4. **README 加一行**：`uv run python -m pydoc mbt` / `uv run pdoc -o docs mbt`。这一步成本几乎为零，却能消除本次最大的一笔无效探索。
5. **字段口径表机器生成**：从 `.schema` + 一张人工维护的 `field → {unit, 累计/单季, 频率, 缺失语义}` 表，合并进 `load_financial` 的 docstring 与 `-f` 输出。
6. **报告口径统一**：`rebalance_count` 与 `finalize` 计数对齐，`profit_factor` 定义写进 docstring，`Beat Buy&Hold` 的对照基准在摘要里注明。

## 6. 结论

把六条判据合起来看，msd stack 的设计取向非常清楚：

- 它**不假设使用者会读 wiki**，而是把契约塞进 docstring（可被机器读取）；
- 它**不假设使用者懂前视偏差**，而是把披露日对齐、切片回放做进数据层；
- 它**不假设使用者会写撮合**，而是把现金约束、手数、涨跌停、停牌做成框架不变量；
- 它**不假设使用者只看曲线**，而是开放 `finalize() -> dict` 让行为可断言；
- 它**不假设使用者只跑一次**，而是内建多起点与样本外切分。

这五条"不假设"，正是"Agent 优先"的定义——**它不是"给人用起来更爽"，而是"把 Agent 的已知缺陷（不可自审、易自我欺骗、无直觉、不擅长跨系统拼信息）逐条在框架层面消解掉"**。

因此本文的判断是：**msd stack 在接口形态上已经是一个 Agent 优先的框架**，它把"策略表达"这一层压到了几乎纯粹的 Python 声明式描述（我写的 `strategy/010/davis_double_play.py` 里，除了 TTM 还原与打分这两段业务逻辑，其余全是架构约定），把"正确性"这一层彻底收归框架。

它离"成熟的 Agent 优先"还差最后一公里：**把静默降级改成显式失败**。因为对 Agent 而言，一个会大喊大叫的框架，远胜过一个体贴地帮它兜底的框架——兜底的时候，Agent 并不知道自己错了。
